# Итоговый проект по курсу «Инженерия Искусственного Интеллекта»

В этой папке находится итоговый мини-проект по курсу.  
Проект должен демонстрировать применение методов и инструментов инженерии ИИ: работу с данными, модели, пайплайны, сервис, эксперименты и (по возможности) воспроизводимость.

## 1. Паспорт проекта

- **Название проекта:** Сервис предсказания оттока клиентов банка
- **Автор:** Полоник Дарья Александровна
- **Группа:** УИБО-01-22
- **Контакт:** @Ba_bun

- **Краткое описание (2-4 предложения):**  
  Проект посвящён задаче предсказания оттока клиентов банка на основе табличных данных.  
  Используется открытый датасет Bank Customer Churn Prediction, baseline-модель Logistic Regression и финальная модель CatBoost.  
  Результатом является REST API-сервис, который принимает данные клиента и возвращает предсказание класса оттока и вероятность ухода.

---

## 2. Структура проекта

Проект организован в следующей структуре:

- `README.md` - основной файл проекта с описанием назначения, структуры, требований, установки, запуска и сценария демонстрации.
- - `report.md` – отчёт по проекту (постановка задачи, данные, эксперименты, результаты).
- `requirements.txt` – зависимости проекта (библиотеки Python, необходимые для запуска).
- `self-checklist.md` – чеклист самопроверки проекта перед сдачей.
- `notebooks/` – экспериментальные ноутбуки:
  - `01_eda_data_quality.ipynb` # Разведочный анализ данных
  - `02_feature_analysis.ipynb` # Анализ признаков
  - `03_baseline_logreg.ipynb` # Baseline модель
  - `04_catboost_models.ipynb` # CatBoost и сравнение
- `src/` – основной код проекта:
  - `logging_config.py` — настройка логирования.
  - `main.py` # Упрощенная версия API-сервиса (без логирования)
  - `predict.py` — загрузка модели и выполнение предсказания;
  - `schemas.py` — схемы входных и выходных данных API;
  - `service.py` — запуск API-сервиса;
  - `train.py` — обучение baseline-модели и финальной модели CatBoost, сохранение артефактов.
  - `utils.py` — вспомогательные функции;
- `data/` – демонстрационные/учебные данные:
  - `raw/Churn_Modelling.csv` — исходный открытый датасет;
  - `demo/sample_input.json` — демонстрационный пример запроса к сервису.
- `configs/` – конфигурационные файлы:
  - `config.yaml` — путь к данным, список признаков, параметры разбиения выборки, версия модели;
- `tests/` – тесты (юнит-тесты, простые проверки).
  - `test_sanity.py` — проверка `/health`, `/docs` и доступности `/predict`. 
- `artifacts/` – сохранённые модели, отчёты, результаты экспериментов.
  - `images/` - Графики и визуализации из экспериментов
  - `model.cbm` — сохранённая финальная модель CatBoost;
  - `baseline_pipeline.joblib` — сохранённый baseline-пайплайн Logistic Regression;
  - `metadata.json` — метаданные модели и порядок признаков;
  - `metrics.json` — результаты экспериментов и рассчитанные метрики качества.

## 3. Требования и установка

### 3.1. Требования

- Python `>= 3.10`
- Рекомендуется установленный `git`
- Для контейнерного запуска — `Docker`

### 3.2. Установка окружения

```bash
# Перейти в папку проекта
cd project

# Создать виртуальное окружение
python -m venv .venv

# Активировать окружение
# Windows:
.venv\Scripts\activate

# Linux / macOS:
source .venv/bin/activate

# Установить зависимости
pip install --upgrade pip
pip install -r requirements.txt
```

Перед запуском обучения необходимо убедиться о наличии файла датасета Churn_Modelling.csv по пути: data/raw/Churn_Modelling.csv.

---

## 4. Как запустить проект

### 4.1. Запуск обучения модели

Windows:
```powershell
cd project
.venv\Scripts\activate
python -m src.train
```

Linux / macOS:
```
cd project
source .venv/bin/activate
python -m src.train
```

### 4.2. Запуск сервиса (API)

```bash
cd project
source .venv/bin/activate      
uvicorn src.service:app --host 0.0.0.0 --port 8000
```

Запуск через Docker (опционально):

```bash
cd project
docker build -t bank-churn-service .
docker run -p 8000:8000 bank-churn-service
```

Порт и эндпоинты:

- Сервис по умолчанию поднимается на порту 8000
- Основные эндпоинты: <GET /health> — проверка работоспособности сервиса; <POST /predict> — предсказание оттока клиента.

Проверка работоспособности: 
- Проверка /health: 
  ```bash
  curl http://localhost:8000/health
  ```
  Ожидаемый ответ: {"status":"ok"}
  
- Проверка /predict:
  ```bash
  curl -X POST "http://localhost:8000/predict" \
  -H "Content-Type: application/json" \
  -d '{
    "CreditScore": 619,
    "Geography": "France",
    "Gender": "Female",
    "Age": 42,
    "Tenure": 2,
    "Balance": 0.0,
    "NumOfProducts": 1,
    "HasCrCard": 1,
    "IsActiveMember": 1,
    "EstimatedSalary": 101348.88
  }'
  ```
- Также можно открыть Swagger UI:
  ```bash
  http://localhost:8000/docs
  ```
